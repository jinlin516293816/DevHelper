LLM ​

大型语言模型（LLM，Large Language Model）是一种基于海量文本数据训练的人工智能系统，通过深度学习技术理解和生成人类语言。以下是其核心要点：

1. 基本定义与核心特点 ​

  • 定义：LLM 是参数规模达数十亿至数万亿的神经网络模型，通过分析互联网上的书籍、文章、网页等文本数据，学习语言的统计规律。
  • 特点：
  • 超大规模参数：例如 GPT-4 的参数达 1.8 万亿，使其具备复杂模式识别能力。
  • 自监督学习：通过“预测下一个词”的任务，无需人工标注即可学习语言规律。
  • 多任务通用性：可完成文本生成、翻译、代码编写、问答等多种任务。

2. 技术原理 ​

  • 架构基础：基于 Transformer 模型，核心组件包括：
  • 自注意力机制：动态捕捉词语间的关联（如理解“船员站在甲板上”中“船员”与“甲板”的关系）。
  • 位置编码：标记词语顺序，解决传统模型忽略时序的问题。
  • 多头注意力：从不同角度分析文本，提升理解深度。
  • 训练过程：
  • 预训练：在海量通用文本上学习语言规律（如 GPT-3 使用 45TB 数据）。
  • 微调：针对特定任务（如医疗问答）优化模型表现。

3. 典型应用场景 ​

  • 内容生成：撰写文章、产品描述（如根据关键词生成陶瓷杯文案）。
  • 智能交互：聊天机器人（如 ChatGPT）、客服系统，支持多轮对话。
  • 信息处理：文本摘要、翻译、情感分析。
  • 专业领域：医学诊断辅助、法律文书分析、代码生成。

4. 优势与局限性 ​

  • 优势：
  • 零样本/小样本学习：无需任务专用训练即可执行新任务。
  • 高效语言处理：自动化重复性文本工作，提升效率（如 IT 支持工单处理）。
  • 局限性：
  • 幻觉问题：可能生成看似合理但错误的内容（如虚构“海豚说中文”）。
  • 数据时效性：训练数据截止后，无法自动更新知识（如 2023 年后的事件）。
  • 领域适配不足：缺乏企业专有数据时，回答可能不够精准。

5. 未来发展方向 ​

  • 多模态扩展：结合图像、声音等多类型输入（如 GPT-4 支持图文混合问答）。
  • 可控性与安全性：通过人工监督和架构优化减少错误输出。
  • 垂直领域深化：在医疗、法律等专业场景中定制化训练，提升实用性。AGI（通用人工智能）是人工智能领域的前沿概念，指具备人类水平广泛认知能力的智能系统，能够自主适应、学习并解决复杂任务，其核心特征与当前主流 AI 技术（如大语言模型 LLM）存在本质差异。以下从定义、架构、特征及发展现状进行解析：

什么是 tokens ​

在大模型中，Tokens 是模型处理文本时的基本单位 。它可以是一个单词、子词（比如英文单词 “playing” 可能被拆分为 “play” 和 “ing” ）或字符 ，具体取决于模型的设计和分词方式 。不同语言的分词方式有差异，英文常按空格和标点分割，中文需更复杂分词算法。

Tokens 作用显著：

  • 作为模型输入基础 ：模型通过 Tokens 理解文本内容，每个 Token 会被转换为向量供模型处理。
  • 提升计算效率 ：将文本分割成 Tokens 可减少计算量，同时保留语义信息。
  • 支持多语言处理 ：通过子词或字符级别的 Tokens，模型能更好处理不同语言文本。

Tokens 的分词方式多样 ，包括基于规则（如按空格、标点分割英文 ）、基于词典（如中文的 Jieba 分词工具 ）、子词分词（如 BPE 或 WordPiece ） 。而且，Tokens 与模型性能紧密相关：数量影响计算成本，处理 Tokens 越多，计算量越大、耗时越长；大多数模型对输入 Tokens 数量有上限；使用商业 API 时，费用常按 Tokens 数量计算 。

AGI ​

1. 定义与核心理念 ​

AGI（Artificial General Intelligence）旨在创造具备人类综合智能的机器，其核心是通过统一理论框架解释智能现象，实现自主感知、认知、决策与执行。与 LLM 等狭义 AI相比，AGI 强调：

  • 通用性：不局限于预设任务，可处理无限任务并自主生成新任务；
  • 自主性：通过价值驱动（如伦理、情感）调整行为，而非依赖数据标注；
  • 进化能力：自我学习与改进，适应动态环境。

2. 技术架构与关键特征 ​

根据朱松纯教授团队提出的理论框架，AGI 需满足“一个定义、两个完备性、三个特征、八个问题”：

  • 认知架构完备性：覆盖感知、推理、社会协作等能力的统一心智模型；
  • 测试环境完备性：复现真实物理与社会交互的动态场景；
  • 核心特征：
  • 无限任务处理：在复杂环境中解决未预定义的问题（如突发危机应对）；
  • 任务自主生成：基于动机判断下一步行动（如人类自主规划日程）；
  • 价值驱动对齐：通过人类反馈学习伦理，确保行为符合社会规范。

3. 与现有 AI 技术的本质差异 ​

当前主流 AI（如 ChatGPT）属于**“鹦鹉范式”（大数据驱动小任务），而 AGI 需实现“乌鸦范式”**（小数据驱动大任务）：

维度AGI（乌鸦范式）LLM（鹦鹉范式）
任务泛化能力跨领域迁移学习，举一反三依赖特定任务数据，泛化性有限
数据需求少量数据自主推理（如乌鸦利用常识）需海量标注数据训练
价值对齐动态学习人类伦理，灵活调整对齐机制脆弱，易产生偏见/幻觉
具身智能物理交互与环境适应（如机器人）局限于文本生成与问答

AIGC ​

AIGC（人工智能生成内容）是指利用人工智能技术自动生成文本、图像、音频、视频等多模态数字内容的新型生产方式。以下是其核心要点解析：

1. 定义与核心特点 ​

  • 定义：AIGC（AI Generated Content）是继专业生产内容（PGC）、用户生产内容（UGC）后的第三代内容创作方式，通过深度学习、自然语言处理（NLP）等技术实现内容自动化生成。
  • 特点：
  • 多模态输出：可生成文本、图像、音频、视频甚至 3D 模型和代码。
  • 高效性：大幅缩短内容生产周期（如电商文案生成仅需数秒）。
  • 低成本：企业人力成本可降低 50%以上。

2. 技术原理 ​

AIGC 的技术核心包括以下模型与架构：

  • 生成对抗网络（GAN）：早期主流技术，通过生成器与判别器的对抗提升内容真实性，但存在分辨率低、输出不稳定问题。
  • 扩散模型（Diffusion Model）：通过逐步降噪生成高分辨率图像，成为当前主流技术（如 DALL-E、Midjourney）。
  • 大语言模型（LLM）：如 GPT 系列，支撑文本生成与复杂推理，结合检索增强生成（RAG）优化结果准确性。
  • 多模态融合技术：如 CLIP 模型，实现文本与图像的跨模态对齐，支持“文生图”“图生视频”等复杂任务。

3. 应用场景 ​

AIGC 已渗透 30+行业，典型场景包括：

  • 内容创作：
  • 文本：新闻稿、小说、广告文案生成（如 ChatGPT、KIMI）。
  • 图像：广告设计、游戏原画（如 Midjourney）、照片修复。
  • 视频：影视分镜脚本、短视频自动化剪辑（如 Sora 模型）。
  • 企业服务：
  • 智能客服：7×24 小时多轮对话与情绪识别。
  • 数据分析：生成投资报告、市场预测。
  • 教育与科研：
  • 个性化学习计划生成、药物分子结构模拟。
  • 元宇宙：构建虚拟角色、场景及互动内容，增强沉浸式体验。AGI（通用人工智能）与 AIGC（生成式人工智能）是人工智能领域两个关键但本质不同的概念，二者在目标定位、技术实现和应用场景上存在显著差异。以下是系统化的对比分析：

  • 需突破"乌鸦范式"：通过小样本学习实现跨领域迁移（如仅观察 10 次实验即掌握物理定律）

MCP ​

MCP（Model Context Protocol，模型上下文协议）是由 Anthropic 主导提出的开放协议标准，旨在为大型语言模型（LLM）与外部工具、数据源建立统一的交互接口，解决传统 AI 应用开发中工具集成碎片化的问题。以下是其核心解析：

1. 定义与核心价值 ​

MCP 被类比为 AI 领域的 "USB-C 接口"，通过标准化协议实现：

  • 统一互联：替代传统 Agent 开发中需为每个工具定制接口的模式，允许 LLM 通过单一协议连接数据库、API、本地文件等多样化资源。
  • 生态共建：服务商遵循 MCP 标准接入工具，开发者无需重复适配，可快速构建复杂 AI 应用。
  • 安全可控：数据访问权限由用户授权，避免敏感信息外泄（如本地文件处理无需上传云端）。

2. 架构与核心组件 ​

MCP 采用 客户端-服务器架构，包含三个核心角色：

组件功能描述示例场景
MCP Host用户直接交互的 AI 应用，负责发起请求与管理上下文Claude 桌面版、Cursor IDE、智能 Agent
MCP Client内置于 Host 的协议客户端，与 Server 保持 1:1 连接，处理消息路由与权限控制IDE 中的工具调用模块
MCP Server提供工具、数据资源与提示模板的轻量级服务程序，支持本地/远程部署文件系统服务、数据库查询接口、邮件发送 API

3. 工作原理 ​

MCP 通过 标准化通信流程 实现 AI 与工具的交互：

  1. 请求触发：用户向 Host（如 AI 编程助手）提出需求（例："查询上周销售数据"）。
  2. 协议协商：Host 内的 Client 识别需调用的工具（如数据库查询），向对应 Server 发送 JSON-RPC 格式请求。
  3. 权限验证：Server 执行操作前请求用户授权，确保数据安全（如弹窗确认是否允许访问财务系统）。
  4. 执行反馈：Server 返回结果（如 CSV 数据表），Client 将其整合至模型上下文，生成最终响应（如可视化图表+分析结论）。

4. 技术优势对比 ​

与传统方案（如 Function Call）相比，MCP 的创新性体现在：

维度MCPFunction Call
协议开放性跨平台通用标准，支持多厂商工具接入绑定特定 LLM 平台（如 OpenAI）
数据安全性本地资源处理无需云端传输，权限由用户实时控制依赖平台数据策略，存在泄露风险
开发成本一次开发即可接入所有兼容 MCP 的 AI 应用需为不同 LLM 重复适配接口
生态扩展性工具开发者可自主发布服务，形成应用市场受限于平台审核与分发机制

5. 典型应用场景 ​

  • 智能编程：在 IDE 中，模型通过 MCP 实时调用代码库搜索、数据库查询等工具，辅助开发者理解项目上下文。
  • 企业自动化：AI 自动完成 "读取本地 Excel→ 筛选数据 → 发送邮件提醒" 的端到端流程，无需手动操作。
  • 数据分析：结合 MCP 连接的 BI 工具，模型直接生成可视化报告并更新至协作平台。

AI Agent ​

AI Agent（人工智能代理）是一种能够自主感知环境、进行推理决策并执行任务的智能系统，其核心在于结合大语言模型（LLM）的推理能力与工具调用技术，实现复杂任务的自动化处理。以下是其核心要点解析：

1. 定义与核心特性 ​

AI Agent 被定义为**“以大语言模型为大脑驱动的系统，具备自主理解、感知、规划、记忆和使用工具的能力，可自动化执行复杂任务”**。其核心特性包括：

  • 自主性：仅需给定目标即可独立完成任务，无需持续人工干预（如 OpenAI 的 Operator 智能体可自动完成订餐、购票等操作）；
  • 多模态感知：能处理文本、图像、声音等多源信息（例如通过视觉识别商品图片，结合语音指令完成电商下单）；
  • 动态学习：通过反思过往数据优化行为（如从客服对话中总结用户偏好以提升服务效率）；
  • 工具调用：集成 API、数据库等外部资源（如调用天气 API 获取数据辅助出行规划）。

2. 技术架构与核心模块 ​

根据研究与实践，AI Agent 的技术架构可分为以下模块：

  1. **大脑（Brain）**以 LLM 为核心，负责推理、规划和记忆管理，通过思维链（CoT）、RAG（检索增强生成）等技术分解复杂任务。例如，复旦大学提出的框架中，大脑模块能根据环境状态生成子任务并调用工具。
  2. **感知（Perception）**整合多模态输入（如视觉传感器、语音识别），支持跨模态信息融合（如通过图片识别用户情绪并调整对话策略）。
  3. **执行（Action）**包括软件接口调用（如发送邮件 API）和物理设备控制（如自动驾驶汽车的机械操作）。

3. 与传统 AI 技术的区别 ​

维度AI Agent传统 AI（如聊天机器人）
任务复杂度处理多步骤、跨工具任务（如旅行规划）限于单轮问答或简单指令执行
自主性主动规划并动态调整策略依赖预设规则或提示词（Prompt）
交互方式支持多模态输入与物理执行以文本对话为主
学习能力通过反馈优化长期表现需人工更新知识库

例如，传统客服机器人仅能回答预设问题，而 AI Agent 可结合用户历史订单、实时库存数据，主动推荐替代商品并完成退款流程。

4. 应用场景与典型案例 ​

  • 电商领域：数字员工代理全程服务（如从商品推荐到物流跟踪），微盟等企业已布局万人级 Agent 团队；
  • 智能制造：工厂智能体平台协调设备维护、生产排程（如泛微网络的 Xiaoe.AI 平台）；
  • 自动驾驶：通过感知交通环境实现决策执行（如谷歌 DeepMind 的机械臂 Agent）；
  • 企业服务：自动化流程处理（如微软 M365 Copilot 集成 Agent 功能处理客户工单）。

5. 技术挑战与未来趋势 ​

  • 挑战：
  • 复杂环境适应性不足（如突发交通状况的实时响应）；
  • 安全风险（如 API 调用权限管理）。
  • 趋势：
  • 垂直领域深化：医疗、金融等场景定制化（如阿里“通义千问”接入多业务线）；
  • 人机协作模式：形成“人类+Agent”混合工作流（如设计师与 AI 共同完成创意提案）。

RAG ​

据 Gartner 预测，到 2028 年 15%的日常工作决策将由 Agent 完成，其商业化落地正加速推进（如亚马逊 Bedrock Agents 赋能企业 AI 开发）。RAG（Retrieval-Augmented Generation，检索增强生成）是一种通过整合外部知识库来增强大语言模型（LLM）性能的技术框架。其核心思想是通过动态检索与用户查询相关的信息，将这些信息作为上下文输入模型，从而提升生成内容的准确性、时效性和可解释性。以下是其核心要点解析：

一、RAG 的诞生背景 ​

大语言模型（LLM）虽具备强大的生成能力，但存在以下局限性：

  1. 幻觉问题：LLM 基于概率生成文本，可能输出看似合理但缺乏事实依据的内容（如虚构历史事件时间线）。
  2. 数据时效性：模型训练数据存在截止时间，无法实时更新（如 ChatGPT 的知识截止至 2021 年）。
  3. 领域适配不足：通用模型缺乏企业私有数据，难以满足垂直场景需求（如医疗诊断需结合最新病例库）。
  4. 隐私与安全：企业敏感数据无法直接用于云端模型训练。

RAG 通过动态检索外部知识库，将最新、专有的信息注入生成过程，有效弥补上述缺陷。

二、RAG 的核心流程 ​

RAG 的典型工作流程分为三个阶段：

  1. 检索（Retrieval）
  2. 知识库构建：将本地文档（PDF、TXT、数据库等）切分为文本块，编码为向量并存入向量数据库（如 Faiss）。
  3. 查询处理：将用户问题转换为向量，通过相似度计算召回 Top-K 相关文档。
  4. 技术关键点：文本分块策略、向量编码模型选择（如 BERT、GLM）、检索算法优化（如混合检索结合关键词与语义匹配）。
  5. 增强（Augmentation）
  6. 上下文融合：将检索结果与用户问题拼接，构建增强后的 Prompt（如模板化提示：“基于以下资料回答：{context}，问题：{query}”）。
  7. 优化方向：去重冗余信息、优先级排序、噪声过滤（如基于置信度阈值）。
  8. 生成（Generation）
  9. 可控输出：LLM 基于增强后的 Prompt 生成答案，通过检索内容约束减少幻觉。
  10. 扩展能力：支持多模态输出（如结合检索到的图表生成分析报告）。

三、RAG 的技术优势 ​

相较于直接使用 LLM 或微调（SFT），RAG 具备以下优势：

维度RAG传统微调（SFT）
数据时效性动态更新知识库，实时整合新数据依赖静态训练数据，更新需重新训练模型
可解释性展示检索来源，增强结果可信度黑盒生成，难以追溯依据
成本与扩展性无需重新训练模型，降低算力消耗需标注数据和高昂训练成本
领域适配快速对接垂直领域知识库需针对每个领域单独微调
隐私安全本地知识库隔离敏感数据需上传数据至云端训练，存在泄露风险

四、典型应用场景 ​

  1. 智能问答系统：结合企业知识库提供精准客服回答（如金融产品咨询）。
  2. 内容生成：基于最新数据生成市场分析报告（如整合实时财报数据）。
  3. 学术研究：检索论文库辅助文献综述撰写。
  4. 法律与医疗：引用法规条文或医学指南生成诊断建议。

五、技术挑战与优化方向 ​

  1. 检索精度：长尾查询召回率低，需优化分块策略与混合检索算法。
  2. 上下文长度限制：大模型 Token 限制影响多文档整合，可通过摘要提取或层次化检索缓解。
  3. 多模态支持：扩展至图像、表格等非文本数据的检索与生成（如 PDF 图表解析）。
  4. 动态更新机制：实现知识库的增量更新与版本管理。

附：RAG 与其他技术的协同 ​

  • 与 Agent 结合：作为 Agent 的知识组件，为其决策提供实时数据支持。
  • 与 MCP 协议集成：通过标准化接口连接多源数据库，提升检索效率。

RAG 通过“外部知识检索+生成控制”的模式，已成为解决 LLM 落地痛点的关键技术。随着多模态检索、小样本学习等技术的发展，其应用边界将进一步扩展。

向量数据库的优缺点 ​

优点 ​

  1. 高效处理高维数据向量数据库专为高维向量设计，通过优化存储结构（如乘积量化 PQ）和索引算法（如 HNSW 分层图索引），可快速完成相似性搜索，适用于图像、音频等非结构化数据的处理。例如，HNSW 算法通过分层图结构将搜索复杂度从线性降低至对数级，实现百亿级向量的秒级检索。
  2. 扩展性与分布式支持支持水平扩展和云计算架构，可处理 PB 级数据量。例如，Milvus 等数据库通过分布式架构实现海量数据的高效管理，满足高并发场景需求。
  3. 多模态与实时性支持文本、图像、音频等跨模态检索（如以图搜图、语义搜索），且多数支持实时数据更新，无需全量重建索引。例如，RAG 应用中通过动态更新知识库向量，确保生成答案的时效性。
  4. 优化 AI 模型训练作为大模型的外挂知识库，可提升训练效率。例如，通过特征提取和数据清洗，减少无效语料对模型的干扰，降低训练成本。

缺点 ​

  1. 事务处理能力弱相比传统关系型数据库，向量数据库在 ACID 事务支持、复杂查询（如多表关联）上表现不足，更适合单一向量检索场景。
  2. 存储与计算成本高高维向量存储占用空间大（如千维向量单条需数 KB），且相似性计算（如余弦相似度）消耗大量算力，硬件成本显著高于传统数据库。
  3. 查询效率受维度限制向量维度越高，索引构建和搜索耗时越长。例如，LSH 算法在处理超大规模数据时召回率下降明显。
  4. 技术成熟度不足多数产品处于商业化早期，功能稳定性与生态工具链（如监控、备份）不完善，需专业团队运维。

向量模型的优缺点 ​

优点 ​

  1. 支持部分匹配与语义理解通过非二元权重分配（如 TF-IDF 算法），向量模型可捕捉语义相关性，优于传统关键词匹配。例如，在搜索“人工智能医疗应用”时，能召回未包含关键词但语义相关的文档。
  2. 动态排序与结果优化基于余弦相似度等度量对结果排序，返回按相关度降序排列的文档，提升用户体验。
  3. 灵活适配多场景可通过调整权重算法（如倒排文档频率 IDF）适应不同领域需求，如医疗文本检索与电商推荐系统的差异化优化。

缺点 ​

  1. 高维计算复杂度向量模型需处理数百至数千维数据，计算资源消耗大，且对噪声敏感（如嵌入模型误差会导致相似度误判）。
  2. 权重分配依赖数据质量术语权重（如 TF-IDF）依赖语料库统计特性，若数据分布不均（如领域术语稀缺），可能导致检索偏差。
  3. 可解释性有限向量空间中的语义关系缺乏直观解释，难以追溯具体影响检索结果的特征维度，降低调试效率。

总结 ​

向量数据库与向量模型共同支撑了 AI 时代的高效数据处理，但其技术局限（如高成本、复杂度）也制约了落地深度。未来可能向多模态融合（结合图数据库）、轻量化索引（如量化压缩）等方向演进，同时与传统数据库的功能集成（如 PostgreSQL 的 pgvector 扩展）或成为趋势。

A2A ​

A2A（Agent to Agent Protocol）是谷歌于 2025 年推出的开源协议，旨在为不同框架和供应商开发的 AI 智能体（Agent）提供标准化的协作方式，实现跨平台、跨系统的多智能体协同工作。该协议通过统一通信规范和安全机制，解决了智能体间互操作性差、协作效率低等核心问题。

一、核心功能与工作原理 ​

  1. 能力发现机制每个智能体通过**"Agent Card"（智能体卡片）**以 JSON 格式描述自身能力（如数据处理、图像生成等），其他智能体可基于此快速匹配任务需求。例如财务分析智能体会公开其支持的数据类型和接口规范，供其他智能体调用。
  2. 任务生命周期管理协议定义**"Task"（任务）**对象，支持即时任务和长周期任务（如持续数天的市场分析）。任务状态实时同步，智能体可动态调整执行策略。例如供应链规划中，库存管理智能体与物流智能体持续交换库存变动和运输进度数据。
  3. 多模态协作通信支持文本、图像、视频、Web 表单等多种交互形式，通过**"Part"（内容片段）**协商用户体验。例如智能体生成分析报告时，可同时返回数据图表（image/png）和结构化数据（application/json），供接收方按需解析。
  4. 安全与认证体系集成企业级身份验证（如 OAuth 2.0）和权限控制，确保跨组织协作的安全性。例如医疗场景中，患者数据处理智能体需通过 HIPAA 合规认证才能接入系统。

二、设计原则 ​

  1. 非结构化协作允许智能体在不共享内存和上下文的条件下协作，保留各自原生能力。例如招聘场景中，简历筛选智能体与背调智能体无需了解对方内部逻辑即可协同工作。
  2. 技术兼容性基于 HTTP/2、SSE（服务器推送事件）、JSON-RPC 等成熟协议构建，降低企业集成成本。开发者无需改造现有 IT 基础设施即可接入。
  3. 企业级扩展能力支持从秒级响应任务到持续数周的复杂流程，例如制造业中设备预测性维护智能体需持续监控传感器数据并协调维修资源。

三、典型应用场景 ​

  1. 企业自动化供应链场景中，库存管理、物流调度、采购预测等智能体通过 A2A 实时同步数据，实现动态补货和成本优化。某案例显示采用 A2A 后库存周转率提升 27%。
  2. 跨平台集成整合 CRM、ERP 等系统智能体，例如销售智能体自动将客户需求同步至生产排程智能体，触发定制化生产流程。
  3. 复杂任务协作招聘场景中，主智能体协调人才库搜索、薪酬分析、面试安排等子智能体，候选人筛选周期从 3 天缩短至 4 小时。

四、与 MCP 协议的差异 ​

维度A2A 协议MCP 协议
定位智能体间协作标准（应用层）智能体与工具连接标准（接口层）
核心功能任务分配、状态同步、跨平台通信工具调用、数据访问、权限管理
协作模式对等协作（Agent↔Agent）主从协作（Agent→ 工具）
典型应用多智能体联合决策单智能体调用外部 API/数据库

两者形成互补：MCP 为单个智能体提供"工具使用能力"，A2A 则实现"智能体集群协作"，共同构建完整 AI 生态。

五、技术价值与趋势 ​

  1. 降低开发成本企业无需为不同智能体开发定制接口，集成成本平均减少 65%。
  2. 催生智能体经济推动"智能体商店"生态，开发者可发布专业化智能体（如法律合同审查 Agent）并通过调用次数获利。
  3. 加速 AGI 进程通过大规模智能体协作，逐步实现复杂环境下的自主推理与任务分解，为通用人工智能（AGI）奠定基础。

当前已有 50+企业接入 A2A 生态，包括 Salesforce、MongoDB 等，预计 2026 年全球 80%的企业级 AI 应用将采用该协议。
