2. AI聊天框的通信方式 ​

问题：AI聊天框的通信方式有哪些？各自有什么优缺点？ ​

答案：

1. 轮询（Polling）

  • 原理：客户端定期向服务器发送请求，查询是否有新消息
  • 优点：实现简单、兼容性好
  • 缺点：浪费资源、延迟高、服务器压力大
javascript
// 轮询示例
function pollMessages() {
  fetch('/api/messages')
    .then(res => res.json())
    .then(messages => {
      updateChat(messages);
    });
}

// 每2秒轮询一次
setInterval(pollMessages, 2000);

2. 长轮询（Long Polling）

  • 原理：客户端发送请求后，服务器保持连接直到有新消息或超时
  • 优点：减少请求次数、实时性比普通轮询好
  • 缺点：服务器资源占用多、连接管理复杂
javascript
// 长轮询示例
function longPolling() {
  fetch('/api/messages?longPolling=true')
    .then(res => res.json())
    .then(messages => {
      updateChat(messages);
      longPolling(); // 再次请求
    })
    .catch(() => {
      setTimeout(longPolling, 1000); // 出错后重试
    });
}

3. Server-Sent Events (SSE)

  • 原理：服务器单向向客户端推送数据，客户端监听
  • 优点：实时性好、服务器端简单、HTTP标准
  • 缺点：只能服务器到客户端、不支持二进制数据
javascript
// 客户端 SSE 示例
const eventSource = new EventSource('/api/messages/stream');

eventSource.onmessage = (event) => {
  const message = JSON.parse(event.data);
  updateChat(message);
};

eventSource.onerror = (error) => {
  console.error('SSE error:', error);
};

4. WebSocket

  • 原理：全双工通信，客户端和服务器可以同时双向通信

  updateChat(message);

  console.error('WebSocket error:', error);
};

// 发送消息

  socket.send(JSON.stringify({ type: 'message', content }));

2. 流式响应模式

javascript
// 流式返回响应
async function sendMessageStream(prompt) {
  const response = await fetch('/api/chat/stream', {
    method: 'POST',
    body: JSON.stringify({ prompt })
  });

  const reader = response.body.getReader();
  const decoder = new TextDecoder();
  let result = '';

  while (true) {
    const { done, value } = await reader.read();
    if (done) break;
    result += decoder.decode(value);
    updateChat(result); // 实时更新UI
  }
  return result;
}

3. 使用 Server-Sent Events (SSE) 的流式响应

javascript
async function sendMessageSSE(prompt) {
  const response = await fetch('/api/chat/sse', {
    method: 'POST',
    body: JSON.stringify({ prompt })
  });

  const eventSource = new EventSource('/api/chat/sse');
  let result = '';

  eventSource.onmessage = (event) => {
    if (event.data === '[DONE]') {
      eventSource.close();
      return;
    }
    result += event.data;
    updateChat(result);
  };
}

使用流式响应的原因：

  1. 改善用户体验：用户可以立即看到部分内容，而不是等待整个响应
  2. 降低感知延迟：即使总响应时间相同，流式响应让用户感觉更快
  3. 适合长文本：AI生成的内容可能很长，流式响应可以逐步展示
  4. 资源优化：服务器可以边生成边发送，不需要在内存中保存整个响应

OpenAI API 流式响应示例：

javascript
import OpenAI from 'openai';

const openai = new OpenAI();

async function chatWithGPT() {
  const stream = await openai.chat.completions.create({
    model: 'gpt-4',
    messages: [{ role: 'user', content: 'Hello!' }],
    stream: true, // 开启流式响应
  });

  let result = '';
  for await (const chunk of stream) {
    result += chunk.choices[0]?.delta?.content || '';
    updateChat(result); // 实时更新
  }
}

// 存储对话历史
const conversationHistory = [
  { role: 'user', content: 'Hello!' },

// 发送消息时将历史一起发送
async function sendMessage(newMessage) {
  const messages = [...conversationHistory, { role: 'user', content: newMessage }];

    method: 'POST',

  });
  
  const data = await response.json();
  conversationHistory.push(
    { role: 'user', content: newMessage },
    { role: 'assistant', content: data.content }
  );
}

2. 上下文窗口管理（Token计数）

javascript
// 估算token数量（OpenAI算法）
function estimateTokens(messages) {
  return messages.reduce((total, msg) => {
    return total + msg.content.length / 4; // 简化估算
  }, 0);
}

// 截断上下文，保持在token限制内
function trimContext(messages, maxTokens = 4000) {
  let trimmedMessages = [...messages];
  
  while (estimateTokens(trimmedMessages) > maxTokens && trimmedMessages.length > 1) {
    trimmedMessages.shift(); // 移除最早的消息
  }
  
  return trimmedMessages;
}

// 使用AI压缩旧对话
async function compressContext(messages) {
  if (messages.length <= 2) return messages;

  const oldMessages = messages.slice(0, -1);
  const latestMessage = messages[messages.length - 1];

  const compressionPrompt = `Summarize the following conversation in detail, keeping important information:
${JSON.stringify(oldMessages)}
SUMMARY:`;

  const response = await fetch('/api/compress', {
    method: 'POST',
    body: JSON.stringify({ prompt: compressionPrompt })
  });
  
  const summary = await response.json();
  
  return [
    { role: 'system', content: `Previous conversation summary: ${summary}` },
    latestMessage
  ];
}

Prompt Engineering ​

1. 基础概念 ​

问题：什么是 Prompt Engineering？为什么对前端开发很重要？ ​

答案：

**Prompt Engineering（提示词工程）**是指设计和优化提示词以获得更好的AI输出的过程。

重要性：

  1. 效率提升：好的提示词可以更快得到想要的结果
  2. 质量保证：精确的提示词产生更高质量的代码
  3. 成本控制：减少无效尝试，降低API成本
  4. 最佳实践：是AI时代开发者的必备技能

问题：好的提示词应该包含哪些元素？ ​

答案：

一个好的提示词通常包含：

  1. 角色设定：告诉AI扮演什么角色
  2. 任务描述：明确要做什么
  3. 上下文信息：提供必要的背景信息
  4. 格式要求：指定输出的格式
  5. 约束条件：设定限制和边界
  6. 示例参考：提供好的输出示例

示例：

你是一位经验丰富的前端架构师，请帮我设计一个用户登录组件。

要求：
- 使用 React + TypeScript
- 包含邮箱和密码字段
- 有表单验证
- 使用 Tailwind CSS 样式
- 使用受控组件模式

输出格式：
- 先列出组件文件结构
- 然后是完整的代码实现
- 最后是使用示例

AI辅助开发最佳实践 ​

1. 何时使用AI ​

问题：在前端开发中，什么情况下适合使用AI辅助？ ​

答案：

适合使用AI的场景：

  1. 代码生成：快速生成通用组件、工具函数
  2. 代码解释：理解复杂代码、学习新框架
  3. 代码优化：重构代码、优化性能
  4. 文档编写：生成API文档、代码注释
  5. 测试编写：生成单元测试、e2e测试
  6. Bug修复：快速定位和解决问题
  7. 学习新技术：快速理解和上手新技术
  8. 架构设计：获取设计建议和架构灵感

谨慎使用AI的场景：

  1. 核心业务逻辑：需要深入理解的业务逻辑
  2. 安全敏感代码：认证、支付等安全相关代码
  3. 复杂算法：需要精确实现的算法
  4. 新技术实验：还不太成熟的技术
  5. 创新性工作：需要创造性思考的工作

1. 安全问题 ​

问题：使用AI辅助开发有哪些安全风险？ ​

答案：

1. 代码安全风险

  • AI可能生成有安全漏洞的代码
  • SQL注入、XSS、CSRF等常见漏洞
  • 不当的错误处理

预防措施：

javascript
// ❌ 不安全的代码
const query = `SELECT * FROM users WHERE name = '${userInput}'`;
// SQL注入风险！

// ✅ 安全的代码
const query = 'SELECT * FROM users WHERE name = ?';
db.query(query, [userInput]); // 参数化查询

  { role: 'system', content: '你是一个内容分析助手' },

// 不同Agent分工协作
async function multiAgentDevProject(projectSpec) {
  const architectAgent = new ArchitectAgent();
  const developerAgent = new DeveloperAgent();
  const testerAgent = new TesterAgent();
  const reviewerAgent = new ReviewerAgent();
  
  // 1. 架构师Agent设计架构
  const architecture = await architectAgent.design(projectSpec);
  
  // 2. 开发Agent实现代码
  const code = await developerAgent.implement(architecture);
  
  // 3. 测试Agent编写测试
  const tests = await testerAgent.createTests(code);
  
  // 4. 审查Agent检查代码
  const review = await reviewerAgent.review(code);
  
  // 5. 迭代优化
  const finalCode = await developerAgent.refine(code, review, tests);
  
  return finalCode;
}

问题：你在前端开发中如何使用AI辅助？ ​

回答：

我在前端开发中会在多个阶段使用AI辅助：

1. 需求分析阶段

  • 让AI帮助梳理功能点
  • 获取技术选型建议

2. 架构设计阶段

  • 让AI提供架构方案
  • 讨论设计模式的使用
  • 评估技术风险

3. 代码实现阶段

  • 使用AI生成组件模板
  • 让AI写工具函数
  • 用AI辅助实现复杂逻辑
  • 让AI解释不熟悉的代码

4. 测试阶段

  • 让AI生成单元测试
  • 用AI分析测试覆盖率
  • 使用AI辅助Debug

5. 文档阶段

  • 让AI生成API文档
  • 用AI写代码注释
  • 让AI帮助整理开发文档

但我也有自己的原则：

  • AI生成的代码必须经过审查
  • 核心业务逻辑自己把控
  • 安全相关的代码不依赖AI
  • 始终保持对代码的理解

举个具体例子： 开发一个用户管理系统时，我会：

  1. 先让AI帮我设计整体架构
  2. 再让AI生成基础的CRUD组件
  3. Review代码后自己修改优化
  4. 让AI生成测试用例
  5. 最后自己写文档

这样既提高了效率，又保证了代码质量。
